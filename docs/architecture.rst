Architecture And Workflows
==========================

Use this section to understand package ownership, the distinction between
control topology and runtime data flow, and the workflows that connect the
four component libraries.

- :doc:`concepts` defines the umbrella boundary and both architecture views.
- :doc:`typical_workflow` follows one study from Problems and Agents through
  Experiments artifacts into Analysis and protocol feedback.
- :doc:`canonical_artifact_flow` is the deterministic, offline all-package
  handoff.
- :doc:`prompt_framing_study` adds the optional local-model participant path.
- :doc:`philosophy` records the ecosystem's methodological commitments.
